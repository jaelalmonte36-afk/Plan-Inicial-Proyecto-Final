P26: Descripción del proceso de negocio al que pertenece la base de datos (Detalladamente)
P28: El proceso de Rehabilitación Integral de Propiedades Residenciales para Renta de Michelle Ultra Services tiene como objetivo gestionar, mediante una base de datos, la transformación de propiedades en mal estado en unidades funcionales, certificadas y listas para alquiler.
P29: El proceso inicia con la normalización de direcciones mediante la tabla DIRECCION (id_direccion, num_casa, calle, ciudad, estado, codigo_postal), que es referenciada por CLIENTE para evitar duplicación de datos. La PROPIEDAD (id_propiedad, num_casa, calle, ciudad, estado, codigo_postal) maneja su dirección directamente, ya que cada propiedad tiene una dirección única e irrepetible.
P30: Se registran las PERSONAS (id_persona, nombre, email, telefono), que sirven como base para los demás actores del sistema. A partir de ahí se registra el CLIENTE (id_cliente, id_persona, id_direccion, empresa) y simultáneamente la PROPIEDAD.
P31: El sistema cuenta con control de acceso mediante la tabla USUARIO (id_usuario, id_persona, rol, username, password_hash, fecha_creacion), que permite gestionar quién opera la base de datos. La relación entre PERSONA y USUARIO es de uno a uno: cada persona registrada puede tener un único usuario del sistema.
P32: Antes de iniciar cualquier proyecto, se realiza una INSPECCION (id_inspeccion, id_propiedad, id_usuario, fecha, condicion_general, notas, costo_estimado) para evaluar el estado de la propiedad. Con esta información se crea el PROYECTO (id_proyecto, id_cliente, id_propiedad, id_inspeccion, fecha_inicio, fecha_estimada_fin), que relaciona al cliente con la propiedad. La inspección es obligatoria: no puede existir un proyecto sin una inspección previa. Inmediatamente se formaliza el acuerdo mediante un CONTRATO (id_contrato, id_proyecto, fecha_firma, monto_acordado, terminos, status).
P33: Se definen los trabajos mediante ESPECIALIDAD (id_especialidad, tipo_trabajo, descripcion) y se detallan en SERVICIO (id_proyecto, id_especialidad, descripcion). Dado que un servicio puede ser ejecutado por varios subcontratistas, se gestiona esa relación mediante SERVICIO_SUBCONTRATISTA (id_proyecto, id_especialidad, id_subcontratista).
P34: Para la ejecución se gestionan los SUBCONTRATISTAS (id_subcontratista, id_persona, status_legal, social_security, licencia_conducir, tiempo_experiencia), vinculados a sus especialidades mediante ESPECIALIDAD_SUBCONTRATISTA (id_especialidad, id_subcontratista), permitiendo que un subcontratista pueda tener más de una especialidad registrada.
P35: Los MATERIALES (id_material, nombre, categoria, costo_unitario_actual) se compran en el momento del trabajo a proveedores externos. Los PROVEEDORES (id_proveedor, nombre, telefono, email, id_direccion) se registran de forma independiente para poder identificar a quién pertenece cada factura y a quién dirigir reclamaciones. La adquisición de materiales se gestiona mediante FACTURA_COMPRA (id_factura_compra, id_proyecto, id_proveedor, fecha, total), que es emitida por el proveedor externo, y su detalle en DETALLE_FACTURA_COMPRA (id_factura_compra, id_material, cantidad, precio_mom).
P36: Una vez conocido el costo total de materiales y mano de obra, se emite la FACTURA_CLIENTE (id_factura_cliente, id_proyecto, fecha, subtotal, impuesto, total) dirigida al cliente. A partir de esta se genera el PAGO (id_pago, id_factura_cliente, precio_mano_obra, pago_inicial, pago_final, total). Las cuotas individuales se registran en CUOTA_PAGO (id_cuota, id_contrato, id_pago, numero_cuota, monto, fecha_pago, metodo_pago, status), que actúa como tabla puente entre CONTRATO y PAGO, dado que las cuotas se acuerdan en el contrato y se ejecutan como pagos.
P37: Durante la ejecución, las actividades se documentan en REPORTE (id_reporte, id_proyecto, id_subcontratista, fecha, tiempo_laboral, observaciones). Al finalizar se emite el CERTIFICADO DE COMPLECION (id_certificado, id_proyecto, id_pago, fecha_finalizacion), y se registra la GARANTIA (id_garantia, id_certificado, fecha_inicio, fecha_vencimiento, descripcion, status) sobre el trabajo realizado.
P38: Finalmente, los clientes pueden dejar su opinión en RESENAS (id_resena, id_certificado, opinion, fecha).
